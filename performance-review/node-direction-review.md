# 프로젝트 방향과 노드 구성의 일치 여부

2026-10-29. 현재 모델과 설치된 워크플로는 변경하지 않았다. 최근 목표인 과거·현재 사진 두 장과 선택 배경으로 자연스러운 무음 만남 영상을 만드는 흐름을 중심으로 검토했다. 캐릭터 시트는 필요할 때 참조를 준비하는 별도 단계이며 영상 제작의 필수 단계로 강제하지 않는다.

## 현재 구성의 적합성

`LoadImage 과거/현재 → 비율 유지 크기 조정 → Qwen 두 인물 합성 → RGB PNG 저장 → H3 첫 프레임 가이드 → 영상 디코딩 → 무음 CreateVideo → SaveVideo`의 구성은 목표와 맞는다. 배경 enable이 참조 이미지와 배경 전용 지시문을 함께 선택하는 점도 맞다. 합성 이미지가 먼저 완성되므로 영상 단계가 얼굴·의상·배경 합성을 다시 독립적으로 수행하는 부담을 줄인다.

현재 통합 37개·합성 21개·영상 17개 노드가 설치되어 있다. 소스와 설치 UI JSON은 직렬화·포트 순서·편집 상태가 달라 바이트 동일하지 않지만, 링크를 노드 ID·출력 슬롯·대상 입력 이름으로 정규화하면 세 파일 모두 연결 의미가 같다. 별도 영상의 내용 차이는 아래에 기록했다.

## 가치가 높은 선택 옵션

1. **합성 먼저 확인 / 영상까지 자동 생성.** 얼굴이나 손이 잘못된 합성으로 영상 연산을 낭비하지 않는 목적이다. 이미 01 합성 전용과 02 영상 전용이 있으므로 당장은 이를 사용하는 것으로 충족한다. SaveImage 자체 미리보기를 재사용하고 PreviewImage를 중복 추가하지 않는다. 통합 화면에서 모드를 제공하려면 SaveVideo 출력 분기를 실제로 실행 대상에서 제외해야 한다. 단순 이미지 스위치나 PreviewImage는 사람의 승인을 기다리며 실행을 정지시키는 장치가 아니다.
2. **이미지 유지 / 영상 동작만 새로 생성.** 이미지 seed와 영상 seed는 이미 KSampler와 RandomNoise에 따로 존재하고 기본 fixed다. 새 노드 없이 두 설정을 사용자 영역에 모아 표시한다. 같은 seed도 모든 환경에서 픽셀 동일성을 보장하지 않는다.
3. **동작 프리셋.** ‘시선 교환·미소’와 ‘시선 교환·가벼운 어깨 토닥임’을 선택하게 한다. 기존 문장 입력과 스위치로 프롬프트를 선택하는 정도면 충분하다. 실제 움직임 강도를 보장하는 모델 파라미터인 것처럼 표시하지 않는다. 프리셋별 결과 검증이 필요하다.
4. **선택적 인물 영역 자르기.** 단체·여백이 많은 사진을 쓰는 경우에만 입력 앞에 기본 ImageCrop과 ON/OFF를 둔다. 기본 OFF이며 얼굴만 지나치게 자르면 의상 단서가 사라진다. 한 사람의 선명한 사진을 쓰는 현재 조건에서는 급하지 않다.

## 지금 추가하지 않을 기능

- 자동 얼굴 교체·얼굴 복원은 얼굴을 다르게 만들 수 있으므로 기본 경로에 추가하지 않는다.
- 추가 원본 사진을 H3에 직접 많이 넣는 옵션은 현재 합성 첫 프레임과 참조가 충돌할 수 있고 메모리 부담이 늘어난다. 얼굴 일치 개선은 미검증이다.
- 업스케일·프레임 보간·더 긴 영상은 현재 관측 VRAM11.4GiB/RAM30.6GiB 조건에서 기본 활성화하지 않는다. 기존5초124프레임을 기준으로 한다.
- 무음 출력에 음성·대사 노드를 추가하지 않는다. 오디오 VAE를 사용자에게 보이는 옵션으로 바꿀 필요도 없다. 무음 파일이라는 사실과 입 움직임의 완전한 억제는 다르다.
- H3 VAE는 이미 내부 타일·시간 청크를 사용하므로 비슷한 기능의 커스텀 노드 팩을 더 설치할 이유가 없다.

## 검사와 한계

`past-present-comfy/build_meeting_workflows.py`, `custom_nodes/codex_video_tools/__init__.py`, README, 테스트와 실제 설치된 `user/default/workflows/Past_Present_Meeting`의 JSON3개를 읽었다. Python으로 링크의 대상 입력 이름을 기준으로 정규화해 소스와 설치본의 연결이 모두 같음을 확인했다. widgets를 대조해 02의 사진·프롬프트·저장명 차이를 확인했다. UTF-8로 읽어 Windows 기본 cp949 디코딩 오류를 해소했다.

이번에는 기능 코드나 워크플로를 바꾸거나 영상 생성을 다시 실행하지 않았다. 직전 검증의 테스트15개 통과와 실제437.511초 생성은 과거 검증 근거이며, 새 제안 옵션이 구현·검증되었다는 뜻은 아니다. 현재 열려 있는 미저장 브라우저 그래프는 검사 대상이 아니며 설치된 저장본 기준이다.
